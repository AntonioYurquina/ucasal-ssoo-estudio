Paginación ​

La paginación es una técnica de gestión de memoria que divide el espacio de direcciones virtuales de un proceso en bloques de tamaño fijo llamados páginas, y la memoria física en bloques del mismo tamaño llamados marcos de página.

Dirección Virtual vs Dirección Física ​

  • Dirección Virtual: Generada por la CPU durante la ejecución de un programa
  • Dirección Física: Dirección real en la memoria RAM

Traducción de Direcciones ​

Una dirección virtual se divide en dos partes:

  • Número de página: Índice en la tabla de páginas
  • Desplazamiento (offset): Posición dentro de la página
|---------------------|------------------|
|   Número de Página  |   Desplazamiento |
|---------------------|------------------|
|<--     n bits    -->|<--   m bits   -->|

¿En qué página está una dirección? ​

Cada página cubre un rango fijo de direcciones. Para saber en cuál cae una dirección virtual, se divide por el tamaño de página y se toma la parte entera (división entera). El resto es el desplazamiento:

Página=⌊Dirección VirtualTamaño de Página⌋Desplazamiento=Dirección VirtualmodTamaño de Página

Y al revés, la página p cubre el rango:

[p×Tamaño de Página, (p+1)×Tamaño de Página−1]

Ejemplo con páginas de 4 KB (4096 bytes): ⌊12315/4096⌋=⌊3,006⌋=3, así que 12315 está en la página 3, que va de 3×4096=12288 a 4×4096−1=16383 (la fila 12K - 16K de la tabla). El desplazamiento es 12315−12288=27.

Fórmula de traducción ​

Dirección Física=(Marco de Página×Tamaño de Página)+Desplazamiento

Tabla de Páginas ​

La tabla de páginas mapea páginas virtuales a marcos físicos. Cada entrada contiene:

  • Número de marco: Marco físico donde está cargada la página
  • Bit de validez (V): Indica si la página está en memoria (1) o no (0)
  • Bit de referencia (R): Indica si la página ha sido accedida
  • Bit de modificación (M): Indica si la página ha sido modificada (dirty bit)

Paginación Multinivel ​

Cuando el espacio de direcciones es muy grande, se utilizan tablas de páginas de múltiples niveles para no tener que mantener toda la tabla de páginas en memoria.

Tabla de Páginas de 2 Niveles ​

La dirección virtual se divide en:

  1. Índice de tabla de nivel 1 (directorio)
  2. Índice de tabla de nivel 2
  3. Desplazamiento

Cálculo de Tamaños ​

Tamaño de Página ​

Tamaño de Página=2bits de desplazamiento

Número de Páginas ​

Número de Páginas=2bits de número de página

Ejemplo: Sistema de 32 bits con páginas de 4K ​

Sistema de 32 bits⇒Espacio de Direcciones=232=4×230 bytes=4 GBTamaño de Página=4K=212 bytes⇒Bits de desplazamiento=12Bits de número de página=32−12=20Número de Páginas=220=1 M páginas

Espacio requerido (1 nivel): ​

Tamaño de Tabla de Páginas=Número de Páginas×Tamaño de cada entrada

Si cada entrada ocupa 4 bytes:

Tamaño de Tabla de Páginas=220×22 bytes=222 bytes=4 MB

Espacio requerido (2 niveles): ​

Si la tabla de nivel 1 tiene 1024 entradas (10 bits) y cada entrada apunta a una tabla de nivel 2 con 1024 entradas (10 bits):

  • Tamaño de página = 4 KB = 2^12 bytes
  • Bits de desplazamiento = 12
  • Bits de nivel 2 = 10
  • Bits de nivel 1 = 10
  • Hay 1 tabla de nivel 1, con 1024 entradas, cada una de 4 bytes
  • Cada tabla de nivel 2 tiene 1024 entradas, cada una de 4 bytes
  • Número total de tablas de nivel 2 = 1024 (una por cada entrada de la tabla de nivel 1)
  • Si todas las tablas de nivel 2 están en memoria, el tamaño total es:
Tamaño total=1×1024×4+1024×1024×4 bytes=4 KB+4 MB=4100 KB

Es decir, con todas las tablas de nivel 2 en memoria, dos niveles ocupan un poco más que uno (4 KB más). La ventaja está en otro lado: cada tabla de nivel 2 cubre 4 MB del espacio virtual (1024 páginas × 4 KB), y las tablas de nivel 2 de las regiones que el proceso no usa no necesitan estar en memoria (Tanenbaum, §3.3.4).

Por ejemplo, un proceso que usa solo 3 regiones de 4 MB (código, datos y pila) necesita 1 tabla de nivel 1 + 3 tablas de nivel 2 = 4 × 4 KB = 16 KB, en lugar de los 4 MB de la tabla de un nivel.

Para la instrucción CMP 12315, #0:

Utilizando el sistema decimal: ​

  • La instrucción CMP 12315, #0 le pide a la MMU que compare el valor de la dirección virtual 12315 con el valor 0
  • La MMU debe traducir la dirección virtual 12315 a una dirección física
  • La dirección 12315 se encuentra en la Página 3: ⌊12315 / 4096⌋ = ⌊3,006⌋ = 3 (rango 12288 a 16383, la fila 12K - 16K)
  • La Página número 3 está asociada al Marco de Página 0(de 0 a 4095) de la Memoria Física (según la tabla de páginas)
  • El desplazamiento dentro de la página es 12315 - (3 * 4096) = 12315 - 12288 = 27
  • Por lo tanto, la dirección física es (0 * 4096) + (27) = 27
  • La Memoria recibe la petición desde la MMU de comparar el valor de la dirección física 27 con el valor 0

Utilizando el sistema binario: ​

  • 12315 en decimal = 0011 0000 0001 1011 en binario
  • Número de página = 0011 (bits más significativos) = 3
  • Desplazamiento = 0000 0001 1011 (12 bits menos significativos) = 27
  • Marco de página = 0 (según tabla)
  • Dirección física = (0 × 4096) + 27 = 0 + 27 = 27
  • La Memoria recibe la petición desde la MMU de comparar el valor de la dirección física 27 con el valor 0

Ejercicio 2: Sistema de 32 bits con 2 niveles ​

En un sistema de 32 bits con:

  • 8 bits para tabla de nivel superior
  • 11 bits para tabla de segundo nivel

Calcular:

a) Tamaño de páginas:

  • Bits restantes para desplazamiento = 32 - 8 - 11 = 13 bits
  • Tamaño de página = 2^13 = 2^3 × 2^10 = 8 KB

b) Número de páginas en espacio virtual:

  • Bits para número de página = 8 + 11 = 19 bits
  • Número de páginas = 2^19 = 2^9 × 2^10 = 512 K páginas

Traducir las siguientes direcciones virtuales (formato: página, desplazamiento). El marco 0 empieza en la dirección física 0 y el resto sigue a continuación.

Antes de traducir hay que verificar, en este orden: que el desplazamiento entre en la página (0 a 2047), que la página exista en la tabla y que esté en memoria (V=1).

a) (1, 481)

  • 481 < 2048 y la página 1 está en la tabla con V=1 → Marco 4
  • Dirección física = 4 × 2048 + 481 = 8192 + 481 = 8673

b) (5, 122)

  • Página 5 no está en memoria (V=0) → Fallo de página
  • Se debe cargar la página desde el disco a un marco libre en memoria
  • Suponiendo que el marco 3 está libre, se carga la página 5 en el marco 3 (también están libres el 0, 1, 5 y 6: cualquiera sirve, y el resultado cambia según cuál use el SO)
  • Actualizar la tabla de páginas: Página 5 → Marco 3, V=1
  • Dirección física = 3 × 2048 + 122 = 6144 + 122 = 6266

c) (2, 1324)

  • 1324 < 2048 y la página 2 está en la tabla con V=1 → Marco 7
  • Dirección física = 7 × 2048 + 1324 = 14336 + 1324 = 15660

d) (9, 021)

  • La tabla solo tiene las páginas 0 a 5: la página 9 no pertenece al proceso → Dirección inválida (el SO envía una señal o termina el proceso: segmentation fault)

e) (3, 2051)

  • Una página de 2048 bytes tiene desplazamientos de 0 a 2047, y 2051 ≥ 2048 → Dirección inválida
  • Como la dirección ya es inválida, no se llega a mirar la tabla de páginas (por eso no se considera el V=0 de la página 3)
