Algoritmos de Reemplazo de Páginas ​

Cuando ocurre un fallo de página y no hay marcos libres en memoria, el sistema operativo debe seleccionar una página para desalojar. Los algoritmos de reemplazo determinan qué página debe ser reemplazada.

Objetivo ​

Minimizar la tasa de fallos de página seleccionando la página que tiene menor probabilidad de ser usada en el futuro cercano.

Algoritmos Principales ​

1. Óptimo (de referencia) ​

Estrategia: Reemplazar la página que se va a usar más lejos en el futuro. Da la menor cantidad de fallos posible, pero no se puede implementar (el SO no conoce las referencias futuras): se usa como referencia para comparar los demás.

2. FIFO (First-In, First-Out) ​

Estrategia: Reemplazar la página que lleva más tiempo en memoria (la más antigua).

Implementación:

  • Cola circular
  • Al cargar una página, se añade al final de la cola
  • Al reemplazar, se elimina del frente de la cola

Ventajas:

  • Muy simple de implementar
  • Bajo overhead

Desventajas:

  • No considera el uso real de las páginas
  • Puede reemplazar páginas muy usadas
  • Sufre la anomalía de Belady: con más marcos puede haber más fallos, porque FIFO no es un algoritmo de pila (las páginas en memoria con n marcos no siempre están entre las que habría con n + 1)
  • Ejemplo clásico: la cadena 0 1 2 3 0 1 4 0 1 2 3 4 produce 9 fallos con 3 marcos y 10 con 4

3. LRU (Least Recently Used) ​

Estrategia: Reemplazar la página que no ha sido usada durante el período más largo.

Principio de localidad: Las páginas usadas recientemente probablemente se usarán pronto.

Implementación:

  • Contador: Timestamp en cada acceso
  • Pila: Mover página accedida al tope
  • Matriz de bits: Actualizar matriz en cada acceso

Ventajas:

  • Buen rendimiento en la práctica
  • Aproxima bien el algoritmo óptimo
  • No sufre la anomalía de Belady (es un algoritmo de pila)

Desventajas:

  • Alto overhead por mantener tiempos de acceso
  • Puede ser costoso encontrar la página LRU

4. Segunda Oportunidad (Clock / Reloj) ​

Estrategia: Aproximación eficiente de LRU usando el bit de referencia (R).

Algoritmo:

  1. Organizar marcos en lista circular (como un reloj)
  2. Mantener puntero "manecilla del reloj"
  3. Al necesitar reemplazo:
    • Si R=0: reemplazar página
    • Si R=1: dar segunda oportunidad (R=0) y avanzar

Ventajas:

  • Más eficiente que LRU (menor overhead)
  • Razonablemente efectivo
  • Usa hardware existente (bit R)

Desventajas:

  • Puede degenerar en FIFO si todas las páginas tienen R=1

5. NRU (Not Recently Used) ​

Estrategia: Usar bits R (referencia) y M (modificación) para clasificar páginas en 4 clases.

Clases (en orden de preferencia para reemplazo):

ClaseRMDescripciónPreferencia
000No referenciada, no modificada1ª (mejor)
101No referenciada, modificada2ª
210Referenciada, no modificada3ª
311Referenciada, modificada4ª (peor)

Algoritmo:

  1. Periódicamente, el SO resetea los bits R de todas las páginas
  2. Al necesitar reemplazo, seleccionar aleatoriamente una página de la clase más baja no vacía

Ventajas:

  • Simple de implementar
  • Distingue entre páginas modificadas y no modificadas
  • Evita escribir páginas no modificadas

Desventajas:

  • Menos preciso que LRU
  • Necesita los bits R y M; si el hardware no los tiene, el SO puede simularlos por software (con fallos de protección en el primer acceso)

Ejercicio 8: Reemplazo de Páginas ​

Dado un sistema con 5 marcos de página:

a) ¿Qué página reemplaza NRU?

La única página de la clase 0 (R=0, M=0) es la 4. Respuesta: página 4.

b) ¿Qué página reemplaza FIFO?

La cargada hace más tiempo es la 1 (tiempo 2400). Respuesta: página 1.

c) ¿Qué página reemplaza LRU?

La de última referencia más vieja es la 3 (tiempo 5200). Respuesta: página 3.

d) ¿Qué página reemplaza Segunda Oportunidad?

La más antigua (1) tiene R=1: se le pone R=0 y pasa al final de la cola. La siguiente (4) tiene R=0. Respuesta: página 4.

e) ¿Hay inconsistencias?

Sí, dos:

  • Bit R de la página 4: fue referenciada en 5580, después que la 3 (5200) y la 1 (5440), pero es la única con R=0. Un reseteo periódico de R no lo explica, porque también habría puesto en 0 los bits R de las páginas 3 y 1.
  • Marcos: hay 5 marcos pero solo se usan 4 (0, 2, 3 y 4); el marco 1 está libre. Un fallo de página cargaría la página en ese marco sin reemplazar ninguna.

Comparación de Algoritmos ​

Conclusión ​

  • Para implementación práctica: Segunda Oportunidad o NRU
  • Si hay recursos: LRU (mejor rendimiento)
  • Si simplicidad es crítica: FIFO (pero con cuidado)
