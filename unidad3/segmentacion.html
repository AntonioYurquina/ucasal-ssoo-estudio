Segmentación ​

La segmentación es una técnica de gestión de memoria que divide el espacio de direcciones de un proceso en segmentos lógicos de tamaño variable, cada uno representando una unidad lógica del programa.

Conceptos Clave ​

¿Qué es un Segmento? ​

Un segmento es una unidad lógica del programa:

  • Código (text segment)
  • Datos globales (data segment)
  • Pila (stack segment)
  • Heap (heap segment)
  • Bibliotecas compartidas

A diferencia de la paginación (bloques de tamaño fijo), los segmentos tienen tamaño variable según las necesidades lógicas del programa.

Memoria Segmentada ​

Dirección Virtual en Segmentación ​

Una dirección virtual se compone de dos partes:

  • Número de segmento (s): Identifica el segmento
  • Desplazamiento (d): Posición dentro del segmento
Dirección Virtual = (s, d)

Tabla de Segmentos ​

Cada proceso tiene una tabla de segmentos que mapea segmentos virtuales a direcciones físicas.

Campos de la Tabla de Segmentos ​

Cada entrada contiene:

CampoDescripción
BaseDirección física inicial del segmento en memoria
LímiteTamaño del segmento (longitud)
PermisosLectura (R), Escritura (W), Ejecución (X)
ValidezBit que indica si el segmento está en memoria

Traducción de Direcciones ​

Algoritmo:

  1. Extraer número de segmento (s) y desplazamiento (d) de la dirección virtual
  2. Verificar que s sea válido (s < número de segmentos)
  3. Buscar entrada s en la tabla de segmentos
  4. Verificar que d < Límite (protección)
  5. Calcular dirección física: Base[s] + d

Ejemplo:

Dirección Virtual: (2, 400)

Tabla de segmentos:
Segmento 2: Base = 1700, Límite = 700

¿Es válido? d (400) < Límite (700) ✓
Dirección Física = 1700 + 400 = 2100

Ejercicio 9: Paginación y Segmentación ​

  • Sistema de 16 bits
  • Páginas de 4 KB
  • Código: 31945 bytes
  • Datos: 15386 bytes
  • Pila: 16870 bytes

a) ¿Se puede ejecutar el programa?

  • Sistema de 16 bits → 2^16 = 65536 bytes (64 KB) de espacio de direcciones
  • Tamaño de página = 4 KB = 4096 bytes
  • Número de páginas = 65536 / 4096 = 16 páginas
  • Tamaño total del programa = 31945 + 15386 + 16870 = 64201 bytes (entraría en 65536, pero cada segmento ocupa páginas enteras)
    • El código ocupa 8 páginas (31945 / 4096 ≈ 7.8 → 8)
    • Los datos ocupan 4 páginas (15386 / 4096 ≈ 3.76 → 4)
    • La pila ocupa 5 páginas (16870 / 4096 ≈ 4.12 → 5)
    • Total páginas necesarias = 8 + 4 + 5 = 17 páginas
  • No se puede ejecutar el programa porque se necesitan 17 páginas y solo hay 16 disponibles.

b) ¿Si el tamaño de la página es de 256 bytes en lugar de 4Kb se puede ejecutar el programa? Considere que se puede asignar todo el direccionamiento de 16 bits al proceso y que una página no puede contener datos de diferentes segmentos.

  • Tamaño de página = 256 bytes
  • Número de páginas = 65536 / 256 = 256 páginas
  • Tamaño total del programa = 64201 bytes
    • El código ocupa 125 páginas (31945 / 256 ≈ 124.8 → 125)
    • Los datos ocupan 61 páginas (15386 / 256 ≈ 60.1 → 61)
    • La pila ocupa 66 páginas (16870 / 256 ≈ 65.9 → 66)
    • Total páginas necesarias = 125 + 61 + 66 = 252 páginas
  • Sí se puede ejecutar el programa porque se necesitan 252 páginas y hay 256 disponibles.

Dada la siguiente tabla de segmentos:

SegmentoBaseLongitud

Traducir las siguientes direcciones virtuales:

a) (0, 230) ​

  • Segmento 0: Base = 23, Límite = 310
  • ¿230 < 310? ✓
  • Dirección física = 23 + 230 = 253

b) (1, 2) ​

  • Segmento 1: Base = 350, Límite = 600
  • ¿2 < 600? ✓
  • Dirección física = 350 + 2 = 352

c) (1, 602) ​

  • Segmento 1: Base = 350, Límite = 600
  • ¿602 < 600? ✗
  • Error: Violación de segmento (Segmentation Fault)
  • El desplazamiento excede el límite del segmento

d) (2, 699) ​

  • Segmento 2: Base = 1700, Límite = 700
  • ¿699 < 700? ✓
  • Dirección física = 1700 + 699 = 2399

e) (3, 400) ​

  • Segmento 3: Base = 2700, Límite = 68
  • ¿400 < 68? ✗
  • Error: Violación de segmento
  • El desplazamiento es mucho mayor que el tamaño del segmento

f) (4, 700) ​

  • Segmento 4: Base = 950, Límite = 450
  • ¿700 < 450? ✗
  • Error: Violación de segmento

Ventajas de la Segmentación ​

1. Refleja la estructura lógica del programa ​

  • Los segmentos corresponden a unidades lógicas (código, datos, pila)
  • Facilita la programación y organización

2. Facilita el compartimiento ​

  • Varios procesos pueden compartir el mismo segmento de código
  • Ejemplo: bibliotecas compartidas (libc, libm)

3. Protección natural ​

  • Permisos por segmento: código ejecutable pero no escribible
  • Datos escribibles pero no ejecutables
  • Un segmento de datos no ejecutable mitiga la inyección de código (por ejemplo, vía buffer overflow), aunque no evita el desbordamiento en sí

4. Crecimiento dinámico ​

  • Segmentos como heap y stack pueden crecer dinámicamente
  • Cada segmento ocupa lo que necesita, sin fragmentación interna (a cambio, sufre fragmentación externa; ver desventajas)

5. Facilita la compilación y enlace ​

  • Módulos se compilan como segmentos separados
  • Enlace dinámico más sencillo

Desventajas de la Segmentación ​

1. Fragmentación externa ​

  • Segmentos de tamaño variable → huecos entre segmentos (checkerboarding, efecto tablero de ajedrez)
  • Requiere compactación periódica (costosa)

2. Complejidad en asignación ​

  • ¿Dónde ubicar un segmento de tamaño variable?
  • Algoritmos: First-Fit, Best-Fit, Worst-Fit

3. Límite en el tamaño de segmentos ​

  • Un segmento debe caber completo en memoria
  • Segmentos muy grandes pueden no caber

4. Tabla de segmentos más compleja ​

  • Cada entrada requiere más información (base + límite + permisos)

Protección y Compartimiento ​

Bits de Protección ​

Cada segmento tiene bits que indican operaciones permitidas:

BitPermisoDescripción
RReadPermite lectura
WWritePermite escritura
XExecutePermite ejecución

Ejemplos típicos:

  • Segmento de código: R-X (lectura y ejecución, sin escritura)
  • Segmento de datos: RW- (lectura y escritura, sin ejecución)
  • Segmento de solo lectura: R-- (solo lectura)

Compartimiento de Segmentos ​

Múltiples procesos pueden compartir el mismo segmento físico:

Proceso A:
  Segmento 1 → Base = 5000 (código compartido)

Proceso B:
  Segmento 2 → Base = 5000 (mismo código)

Ventajas:

  • Ahorro de memoria
  • Consistencia de código
  • Bibliotecas compartidas
