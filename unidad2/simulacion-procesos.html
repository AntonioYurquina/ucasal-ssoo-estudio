Simulación de Procesos en Multiprogramación ​

El modelo probabilístico ​

Cada proceso alterna ráfagas de CPU con esperas de E/S. Llamamos p a la fracción del tiempo que un proceso pasa esperando E/S.

Con n procesos en memoria, la CPU queda ociosa solo si todos esperan E/S al mismo tiempo. Entonces:

Procesos en memoria (n)123...n
CPU ociosapp2p3...pn
CPU ocupada1−p1−p21−p3...1−pn
CPU por proceso1−p1−p221−p33...1−pnn

La última fila es la clave: la CPU ocupada se reparte en partes iguales entre los n procesos.

Duración = tiempo de CPU

La duración de cada proceso son los minutos de CPU que necesita, no el tiempo real que tarda. Por cada minuto real, cada proceso recibe 1−pnn minutos de CPU.

Método paso a paso ​

  1. Armar la tabla de arriba desde n=1 hasta la cantidad máxima de procesos que pueden estar juntos.

  2. Empezar en el horario de llegada del primer proceso.

  3. Con los n procesos activos, calcular:

    • El tiempo real que le falta a cada proceso para terminar:

      Δtterminar=CPU restante1−pnn

    • El tiempo que falta hasta que llegue el próximo proceso.

  4. El evento siguiente es el menor de esos tiempos (Δt). Avanzar el reloj Δt y restar a cada proceso activo la CPU que recibió:

    CPU recibida=Δt×1−pnn

  5. Si un proceso terminó, anotar su horario de fin. Si llegó uno nuevo, agregarlo. Como cambió n, volver al paso 3.

  6. Repetir hasta que terminen todos los procesos.

Pregunta 8 ​

En un sistema de multiprogramación se sabe que el tiempo promedio de espera de E/S es del 50%, dicho promedio se debe a la influencia de cálculos actuariales involucrados en los procesos.

Se desea saber los momentos (en horas y minutos) en que finalizarán cada uno de los siguientes procesos:

ProcesoLlegadaDuración (CPU)
A14:20 hs2 minutos
B14:21 hs2 minutos
C14:26 hs1 minuto

Resolución ​

Con p=0.5: con 1 proceso, cada uno recibe 0.5 de CPU por minuto; con 2 procesos, 1−0.252=0.375.

IntervaloProcesos activosCPU por procesoQué pasa
14:20 → 14:21A0.5A recibe 1×0.5=0.5. Llega B. A: faltan 1.5
14:21 → 14:25A, B0.375A necesita 1.5/0.375=4 min (antes de que llegue C). Cada uno recibe 1.5. A termina
14:25 → 14:26B0.5B necesita 0.5/0.5=1 min. B termina. Llega C
14:26 → 14:28C0.5C necesita 1/0.5=2 min. C termina

Resultado: A termina a las 14:25, B a las 14:26 y C a las 14:28.

Redondeo

Tanenbaum redondea la tabla a 2 decimales (0.375→0.38). Con ese redondeo, A y B terminan unos segundos antes: 14:24:57 y 14:25:57. En el simulador podés elegir cuántos decimales usar en la tabla (o no redondear) para comparar.
