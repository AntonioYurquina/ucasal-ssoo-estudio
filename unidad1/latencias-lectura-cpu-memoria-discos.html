Latencias de lectura: CPU, memoria y discos ​

Cuando un proceso necesita un dato, el costo no es “una lectura”: depende de dónde está ese dato. La diferencia entre registros/caché, RAM, SSD, HDD, cinta o almacenamiento por red es de órdenes de magnitud.

Órdenes de magnitud (referencia) ​

Valores típicos de latencia de acceso (aprox.). Sirven para comparar, no como spec de un hardware concreto.

NivelLatencia típicaEquivalente @ ~3 GHz
Ciclo de CPU / registro~0.3 ns~1 ciclo
Caché L1~0.5–1 ns~2–3 ciclos
Caché L2 / L3~3–20 ns~10–60 ciclos
RAM (memoria principal)~100 ns~300 ciclos
SSD NVMe local~16–50 μs~50k–150k ciclos
SSD por red (p. ej. EBS)~250 μs~750k ciclos
HDD (seek + lectura)~1–10 ms~3M–30M ciclos
Cinta (lectura aleatoria)~1 s o más~3G ciclos

Relacionado: en Lenguaje máquina… el gráfico de costos expresa la misma idea en ciclos de CPU.

RAM vs SSD local ​

Round-trip CPU → RAM ≈ 100 ns. CPU → SSD NVMe local ≈ 50 μs (unas 500× más lento que la RAM). Por eso los sistemas operativos cachean páginas en memoria y evitan ir a disco siempre que pueden.

SSD local vs almacenamiento por red ​

Si el disco “está en la red” del datacenter (volúmenes tipo EBS), cada lectura paga un round-trip de red. Típico: ~250 μs frente a ~50 μs del NVMe local — otro orden de magnitud de latencia por encima del SSD directo.

HDD vs SSD ​

Un HDD necesita mover el brazo y esperar el plato. Una lectura aleatoria suele estar en 1–3 ms. Un SSD moderno puede responder en ~16 μs: cientos de veces más rápido en acceso aleatorio, porque no hay partes mecánicas.

Cinta vs HDD ​

La cinta sigue usándose para archivo masivo (barata, durable), pero una lectura “lejos” del cabezal puede llevar segundos. Un HDD, aunque mecánico, está en el orden de milisegundos.

Qué implica para el SO ​

  • Un proceso bloqueado en E/S puede “desperdiciar” millones o miles de millones de ciclos de CPU potenciales; el planificador aprovecha eso corriendo otros procesos.
  • La jerarquía de memoria (registros → caché → RAM → disco) existe precisamente por estas diferencias de latencia y costo.
  • Accesos secuenciales suelen ser mucho mejores que aleatorios en cinta y HDD; en SSD el layout y el GC también importan.

Para ver cómo se mueven cinta, HDD y SSD “por dentro” (y qué abstrae el SO al leer un archivo), ver Funciones de un Sistema Operativo.
