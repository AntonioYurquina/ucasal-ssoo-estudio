Lenguaje máquina, microprogramación y código assembler ​

Lenguaje máquina ​

  • Conjunto de instrucciones que entiende la CPU
  • Cada CPU tiene su propio lenguaje de máquina
  • Cada instrucción es un número binario

Código Assembler ​

  • Lenguaje de bajo nivel
  • Cada instrucción es una palabra clave
  • Cada instrucción se traduce a una instrucción de lenguaje máquina

Microprogramación ​

  • Técnica que usan algunas CPU para implementar su conjunto de instrucciones (ISA): un microprograma guardado en una ROM dentro de la CPU interpreta cada instrucción de máquina
  • Cada instrucción se ejecuta como una secuencia de microinstrucciones
  • Cada microinstrucción es un número binario que activa señales de control internas
  • Otras CPU (por ejemplo, muchas RISC) no usan microprograma: ejecutan las instrucciones directamente en hardware (control cableado)

Ejecución bloque a bloque: el Program Counter ​

Cuando un proceso está en CPU, no “corre el programa entero de un saque”: la CPU avanza instrucción por instrucción. El Program Counter (PC) es el registro que apunta a la próxima instrucción a ejecutar. Cada ciclo típico es:

  1. Buscar (fetch): copiar en el registro de instrucción (IR) la instrucción a la que apunta el PC y actualizar el PC para que apunte a la siguiente
  2. Decodificar (decode): determinar qué operación es y cuáles son sus operandos
  3. Ejecutar (execute): realizar la operación

Relación con los procesos del sistema operativo ​

Cuando el planificador le asigna la CPU a un hilo, lo que ocurre físicamente es que la CPU empieza a ejecutar sus instrucciones de máquina:

  1. ProcesoLo administra el SO: espacio de direcciones, archivos abiertos y uno o más hilos.
  2. HiloUnidad planificable por el planificador del SO: tiene su propio PC, registros y pila.
  3. Instrucciones de máquinaLo que la CPU ejecuta una por una; el assembler es su forma legible.
  4. MicroinstruccionesEn las CPU microprogramadas, cada instrucción se ejecuta como pasos internos de control.

Ejemplo de flujo: ​

  1. Proceso invoca read() → instrucción syscall
  2. Modo kernel maneja E/S → el hilo se bloquea
  3. Planificador elige otro hilo/proceso
  4. Al llegar la interrupción de E/S, el hilo pasa a Listo

Importancia para entender los procesos ​

  • Planificación y quantum: un hilo ejecuta instrucciones hasta agotar su quantum o hasta bloquearse. Cambiar de contexto tiene un costo (guardar y restaurar registros, TLB, cachés) que impacta el rendimiento.
  • Llamadas al sistema (syscalls): se invocan con instrucciones especiales (p. ej., int/syscall). Implican cambio a modo kernel y operaciones que pueden ser más costosas que instrucciones puramente de usuario.
  • E/S e interrupciones: muchas syscalls disparan E/S que bloquea al hilo hasta que llega una interrupción; durante ese tiempo, el proceso no usa CPU.
  • Microarquitectura: latencias de memoria, predicción de saltos, y el paralelismo interno afectan cuántas instrucciones por ciclo (IPC) logra un proceso.
  • Diagnóstico: leer trazas, comprender fallos de segmentación y medir "CPU-bound" vs "I/O-bound" requiere entender la relación entre assembler y máquina.

Costos de operaciones de CPU ​

A continuación se muestran los tiempos relativos (en ciclos de CPU) de distintas operaciones comunes. Los rangos son aproximados y dependen de la microarquitectura y del contexto de ejecución, pero sirven para tomar perspectiva de órdenes de magnitud.

Ejemplos de código ​

Hola Mundo en JavaScript ​

javascript
console.log("Hola Mundo");

Hola Mundo en Assembler ​

asm
section .data
    message db 'Hola Mundo', 10 ; Mensaje + salto de línea (10 = '\n')
    
section .text
    global _start ; Punto de entrada
    
_start:
    mov eax, 4 ; Llamada al sistema sys_write
    mov ebx, 1 ; Descriptor de archivo stdout
    mov ecx, message ; Dirección del mensaje
    mov edx, 11 ; Longitud: 10 caracteres + salto de línea
    int 0x80 ; Llamada al sistema
    
    mov eax, 1 ; Llamada al sistema sys_exit
    xor ebx, ebx ; Código de salida exitoso
    int 0x80 ; Llamada al sistema

Simulación de un microprocesador ​

La simulación de un microprocesador permite entender cómo funciona el lenguaje máquina y la microprogramación. Una herramienta útil para esto es QtRVSim, un simulador de microprocesadores que permite ejecutar instrucciones en un entorno gráfico.

NOTE

También puedes probar la simulación en línea de Bit Machine para ver como una CPU ejecuta código assembler y lenguaje máquina.
