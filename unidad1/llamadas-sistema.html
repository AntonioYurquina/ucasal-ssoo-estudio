Llamadas al Sistema ​

Las llamadas al sistema (system calls) son el mecanismo utilizado por un proceso en modo usuario para solicitar un servicio al sistema operativo.

Características principales ​

  • Las llamadas al sistema son instrucciones de lenguaje de máquina
  • Se ejecutan en modo kernel
  • Permiten que los procesos realicen tareas restringidas
  • Ejecutan la instrucción TRAP
  • Las llamadas al sistema son la interfaz entre el modo usuario y el modo kernel

Funcionamiento ​

Cuando un programa necesita realizar una operación que requiere privilegios de kernel (como acceder a hardware o a recursos protegidos), debe realizar una llamada al sistema:

  1. El programa prepara los parámetros para la llamada al sistema
  2. El programa ejecuta una instrucción especial (TRAP) que cambia el modo de ejecución de usuario a kernel
  3. El sistema operativo verifica la validez de la solicitud
  4. El sistema operativo ejecuta el servicio solicitado
  5. El sistema operativo devuelve el control al programa en modo usuario

Ejemplo: Llamada al sistema read(fd, buffer, nbytes) ​

La llamada al sistema read() permite a un programa leer datos de un archivo o dispositivo:

  • fd: Descriptor de archivo
  • buffer: Buffer de lectura
  • nbytes: Número de bytes a leer

Llamadas al sistema vs. Procedimientos de biblioteca ​

Llamada al Sistema ​

  • Son costosas en términos de tiempo
  • Se ejecutan en modo kernel
  • Varían según el SO

Procedimiento de Biblioteca ​

  • Es una función definida por una librería
  • Se ejecutan en modo usuario
  • Son independientes del SO

¿Una llamada al sistema se ve distinta de un procedimiento de biblioteca? ​

Se ven iguales. En C, read(fd, buffer, nbytes) se escribe igual que strlen(s): es una llamada a una función. La diferencia está adentro: read() es un procedimiento de biblioteca que prepara los parámetros y ejecuta TRAP para pasar a modo kernel, mientras que strlen() se resuelve completa en modo usuario.

Importancia de saber distinguir entre llamadas al sistema y procedimientos de biblioteca: ​

  • Rendimiento: cada llamada al sistema es mucho más costosa que una llamada común. Hay que cambiar de modo usuario a kernel, guardar el contexto, validar la solicitud y volver. Además, al terminar la llamada, el SO puede elegir ejecutar otro proceso, lo que retrasa todavía más al que la hizo.
  • Bloqueo: una llamada al sistema puede bloquear al proceso (por ejemplo, read() esperando datos del teclado o del disco).
  • Portabilidad: las llamadas al sistema cambian según el SO. Las funciones de biblioteca estándar (como fopen()) son iguales en todos.

Ejemplo: escribir un archivo de a un byte con write() hace una llamada al sistema por cada byte. Con fwrite() o putc(), la biblioteca junta los datos en un búfer y llama a write() pocas veces. El archivo queda igual, pero el programa es mucho más rápido.

Ejemplos comunes de llamadas al sistema ​

  • Gestión de procesos: fork(), exec(), exit(), wait()
  • Gestión de archivos: open(), close(), read(), write()
  • Gestión de directorios: mkdir(), rmdir(), link(), unlink()
  • Gestión de memoria: brk(), mmap(), munmap()
  • Comunicación: pipe(), socket(), connect(), accept()
