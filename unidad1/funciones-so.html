Abstracción de Recursos ​

Ejemplo: leer un archivo ​

Para el programador, leer un archivo parece una operación simple:

c
int fd = open("datos.txt", O_RDONLY);
char buf[4096];
ssize_t n = read(fd, buf, sizeof(buf));
close(fd);

Sin el SO, ese mismo pedido implicaría lidiar a mano con el hardware: saber si el dato está en un SSD, un HDD o una cinta; mover cabezales o esperar a que gire un plato; hablar con controladores; traducir “nombre de archivo” a bloques físicos; y decidir qué hacer mientras la E/S tarda milisegundos o segundos.

Qué facilita el SO al usuario / programador ​

El programador ve…El SO se encarga de…
Un nombre de archivo (datos.txt)Resolver la ruta en el sistema de archivos, permisos y metadatos
Un descriptor (fd)Abrir el archivo, asociarlo al proceso y validar acceso
Un read() a un bufferTraducir a lecturas de bloques, drivers y controlador del dispositivo
Bytes en memoriaCopiar o mapear datos hacia el espacio del proceso (y cachear en RAM)
“La lectura terminó”Bloquear el proceso, atender la interrupción y despertarlo cuando hay datos
Independencia del hardwareOcultar si abajo hay SSD, HDD, cinta, red o una mezcla

En resumen: el SO convierte “quiero estos bytes del archivo” en una secuencia segura de gestión de procesos, memoria, E/S y sistema de archivos. El programador no programa el disco; programa contra la máquina extendida.
